# Hook-Driven Agent Session Registry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and locally install a small hook-driven registry, read-only projection daemon, and animated 15-key Stream Deck plugin that shows Drew's active Claude, Codex, and Kimi sessions.

**Architecture:** Provider hooks invoke one compiled Bun executable, whose shared mutation layer writes active-only session state to SQLite in short transactions. A read-only Bun daemon watches SQLite's `data_version` and atomically publishes a complete surface-neutral snapshot. The official Node.js Stream Deck plugin polls that snapshot, projects stable logical slots onto one bundled 5x3 profile, and owns paging, SVG rendering, animation, settings, and action lifecycle.

**Tech Stack:** TypeScript, Bun and `bun:sqlite` for the core, `bun:test` for focused behavioral tests, the official `@elgato/streamdeck` SDK with Rollup for the Node.js 24 plugin, SQLite WAL, macOS `launchd`, and the official Stream Deck CLI for validation, packaging, linking, and installation.

**Approved spec:** [`docs/superpowers/specs/2026-08-06-hook-driven-session-registry-design.md`](../specs/2026-08-06-hook-driven-session-registry-design.md)

## Global Constraints

- This repository must remain one small TypeScript project. Do not introduce a service framework, ORM, dependency-injection framework, generalized surface SDK, socket server, or web UI.
- Hooks are trusted lifecycle inputs. Do not add provider inventory reads, AgentsView integration, process/window verification, leases, heartbeats, expiry, reconciliation, tombstones, event replay, or incarnation fencing.
- Only the registry mutation layer may write active session state. The daemon and plugin are read-only consumers.
- Keep provider payloads out of persistence and diagnostics. Decode only allowlisted strings, cap every accepted string, and never log prompts, transcripts, tool arguments/output, arbitrary errors, environment variables, or raw input.
- Production components resolve the current user's home with the runtime operating-system API. Do not use the working directory, a literal `~`, or ambient `PATH` to locate installed state.
- The plugin must use the normal official SDK/profile/package path. Do not build a custom HID driver or duplicate Stream Deck host behavior.
- The database stores active state only. End/clear operations delete rows; no history table is added.
- A missed end event may leave a stale row forever. That is an accepted V1 limitation repaired only by the explicit `sessions clear` commands.
- Tests must exercise structured behavior and real SQLite/process boundaries. Do not assert whole generated SQL, shell scripts, manifests, snapshots, or SVG documents as large strings.
- Do not add backward compatibility, legacy-schema import, or automatic database recreation. An unsupported `PRAGMA user_version` is a hard local incompatibility with the fail-open/error behavior in the spec.
- Do not edit Drew's Claude, Codex, or Kimi configuration until the final installation task. Hooks are installed last.
- Do not create a Linear ticket for this repository.
- Run `git status --short` before every staging command and stage only the files named in that task.

```sql
CREATE TABLE active_sessions (
  provider TEXT NOT NULL CHECK (provider IN ('claude', 'codex', 'kimi')),
  session_id TEXT NOT NULL,
  parent_session_id TEXT,
  status TEXT NOT NULL CHECK (status IN ('idle', 'working', 'waiting', 'error')),
  title TEXT,
  project TEXT,
  logical_slot INTEGER,
  opened_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  PRIMARY KEY (provider, session_id),
  FOREIGN KEY (provider, parent_session_id)
    REFERENCES active_sessions(provider, session_id) ON DELETE CASCADE,
  CHECK (
    (parent_session_id IS NULL AND logical_slot IS NOT NULL AND logical_slot > 0)
    OR
    (parent_session_id IS NOT NULL AND logical_slot IS NULL)
  )
) WITHOUT ROWID;

CREATE UNIQUE INDEX active_sessions_unique_slot
  ON active_sessions(logical_slot)
  WHERE logical_slot IS NOT NULL;
```

Set process umask to `0o077` at the CLI boundary. `initializeDatabase` enables WAL, starts one migration transaction, creates version 1, and sets `PRAGMA user_version = 1` before commit. Every open connection executes `PRAGMA foreign_keys = ON`; writable connections also set a short busy timeout. Non-`init` writable opens must set SQLite's create option to false so a missing registry is an error rather than an implicit empty database.

3. Three top-level starts receive slots `1, 2, 3`; deleting slot `2` causes the next new identity to receive `2`; status/metadata changes never move existing slots.
4. Repeating `SessionStart` for one active top-level identity preserves its slot.
5. A child receives `logicalSlot = null`; deleting its parent cascades through nested descendants.
6. Self-parenting, missing parent, cross-provider parentage, top-level-to-child role changes, child-to-top-level role changes, and prospective cycles are ignored with no partial mutation.
7. `SessionEnd` cannot delete a child and `SubagentStop` cannot delete a top-level row.
8. `sessions clear` deletes exactly the selected provider/session composite identity and descendants.

Use row-level assertions, not SQL-text assertions.

- [ ] **Step 3: Implement one transaction boundary and lowest-free allocation**

Use `BEGIN IMMEDIATE`, `COMMIT`, and rollback in `finally`. The allocator query may find the first hole in TypeScript from the sorted non-null slot list; do not add an allocator table.

Event-role behavior is exact:

- `SessionStart` inserts a missing top-level row or resets an existing top-level row to idle while preserving its slot; it ignores an identity currently stored as a child.
- `SubagentStart` inserts a missing child or resets an existing child after validating its prospective parent; it ignores an identity currently stored as a top-level row.
- `Activity`, `Attention`, `Stop`, and `StopFailure` update an existing row only.
- `SessionEnd` deletes an existing top-level row only.
- `SubagentStop` deletes an existing child row only.

Before a child insert/update, follow parent links with a `Set` and a bound no larger than the current row count plus one. Reject the change if the candidate child is encountered or if any referenced parent is absent/wrong-provider. Let the foreign key and partial unique index remain the final backstop.

`clearSession` must first select the row by `(provider, sessionId)`, then delete that exact composite identity in a write transaction. `clearAllSessions` executes `DELETE FROM active_sessions` in one write transaction. Neither command changes schema or recreates a database.
